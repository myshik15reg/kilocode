# Docs Standards (SoT)

## Purpose

Этот документ задаёт единые стандарты для Markdown-документации AlfaFlowAI workflow-pack: структура, ссылки, дедупликация, переносимость, deprecation.

## Normative language

1. MUST означает обязательное требование.
2. MUST NOT означает запрещённое действие.
3. SHOULD означает рекомендацию; отклонение допускается только при явной причине, зафиксированной как evidence.
4. MAY означает опциональное действие.

## 1. Структура знаний (каталоги) MUST быть стабильной

1. `.kilocode/` MUST содержать переносимые правила, воркфлоу, паттерны, skills и шаблоны.
2. `.protocols/` MUST использоваться только как временная рабочая зона конкретной `task`.
3. `temp/` MUST рассматриваться как scratch space и MUST NOT быть источником истины.

## 2. SoT и wrappers MUST быть разделены

1. Каждый набор требований MUST иметь один Source of Truth (SoT).
2. Остальные документы MUST быть thin wrapper и MUST:
    1. ссылаться на SoT;
    2. не переопределять термины;
    3. не дублировать чеклисты и определения.
3. Wrapper MAY добавлять краткую мотивацию и указание "когда читать", но MUST NOT добавлять новые правила.

## 3. Стиль и компактность

1. Документы MUST быть компактными и исполнимыми.
2. Документы уровня entrypoints/rules MUST NOT содержать списки-маркеры (Markdown `-`/`*` list). Используй нумерацию и таблицы.
3. Документы уровня workflows SHOULD избегать списков-маркеров, предпочитая нумерацию и таблицы.
4. Документы уровня skills/patterns MAY использовать списки-маркеры, если это повышает читаемость и не ведёт к дублированию SoT.
5. Quick documents MUST оставаться короткими:
    1. [`QUICK.md`](../QUICK.md:1) MUST содержать только коридор чтения и абсолютные правила.
    2. [`quickref.md`](../workflows/quickref.md:1) MUST быть "меню" процессов и гейтов.
    3. [`overview.md`](../workflows/overview.md:1) MUST быть концептуальной картой без дублирования SoT.

## 4. Ссылки MUST быть проверяемыми

1. Любая ссылка на внутренний файл MUST использовать относительный путь.
2. Ссылка SHOULD указывать строку `:line`, если это увеличивает проверяемость.
3. Документ MUST NOT ссылаться на отсутствующие файлы. Если упоминание условное, оно MUST быть помечено как условное.
4. Факты MUST быть подтверждаемы источником. См. [`evidence-rules.md`](evidence-rules.md:1).

## 5. Переносимость MUST быть явной

1. Любые пути к скриптам MUST следовать SoT [`scripts-entrypoints.md`](../workflows/scripts-entrypoints.md:1).
2. Документы MUST различать три контекста путей:
    1. embedded workflow-pack: `.kilocode/...`;
    2. global install: `~/.kilocode/...` (Unix) и `$HOME/.kilocode/...` (PowerShell);
    3. consuming project: `./.github/...` и `./scripts/...`.
3. Repo-specific знания MUST быть либо:
    1. вынесены в stable evidence под `.kilocode/evidence/`, либо
    2. помечены как пример (example) и не должны быть обязательными для consuming project.

## 6. Deprecation MUST быть безопасным

1. Если файл/правило устаревает, документ MUST:
    1. явно пометить deprecation;
    2. указать replacement ссылкой на SoT;
    3. не ломать ссылки (предпочтительно оставить thin wrapper).
2. Удаление файла MAY быть сделано только после миграции ссылок.

## 7. Minimal doc self-check (без запусков)

1. Проверка ссылок MUST выполняться чтением, не командами.
2. Документ считается корректным, если:
    1. все упомянутые пути существуют либо помечены условными;
    2. термины используются по [`terminology.md`](terminology.md:1);
    3. нет противоречащих друг другу MUST.
