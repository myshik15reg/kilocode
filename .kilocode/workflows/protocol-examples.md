# Примеры протоколов

Назначение: показать форму хорошего протокола. Не копируй эти примеры дословно между проектами.

## Примечания

- Нумеруй требования (R1, R2, ...) для трассируемости.
- Делай план прикладным: шаги, файлы к изменению, матрица покрытия, список задач.
- Полный воркфлоу см. в [`protocol-new.md`](protocol-new.md).

## Пример: протокол фичи (Экспорт пользователей)

### brief.md

```markdown
# Фича: экспорт пользователей

## Требования

- [ ] R1: Экспортировать пользователей в CSV
- [ ] R2: Фильтр по активному статусу
- [ ] R3: Колонки: id, email, created_at
- [ ] R4: Валидация входных данных и авторизация

## Критерии готовности (DoD)

- [ ] API-эндпоинт создан
- [ ] CSV-формат валиден
- [ ] Покрытие = 100% (строки/ветвления/функции)
- [ ] Линтер: 0 ошибок / 0 предупреждений
- [ ] Документация обновлена
```

### plan.md

```markdown
# План

## Шаги

- [ ] S1: Реализовать эндпоинт экспорта (бэкенд).
- [ ] S2: Добавить CSV-форматирование и валидацию.
- [ ] S3: Добавить юнит- и интеграционные тесты (покрытие 100%).
- [ ] S4: Обновить документацию и закрыть протокол.

## Файлы к изменению

- `src/routes/users.ts`
- `src/services/user-export.ts`
- `tests/user-export.test.ts`

## Матрица покрытия требований

| Требование | Шаги   |
| ---------- | ------ |
| R1         | S1, S2 |
| R2         | S1     |
| R3         | S2     |
| R4         | S1, S3 |

## Список задач (опционально)

- [ ] T001 [P] Скелет эндпоинта (`src/routes/users.ts`)
- [ ] T002 CSV-форматирование (`src/services/user-export.ts`)
- [ ] T003 Тесты на успешный сценарий (`tests/user-export.test.ts`)
- [ ] T004 Тесты на краевые случаи и ошибки (`tests/user-export.test.ts`)
```

### execution.md

```markdown
# Лог выполнения

- 2026-01-12: Реализованы эндпоинт и форматирование.
- 2026-01-12: Добавлены тесты и достигнуто 100% покрытие.
- 2026-01-12: Обновлена документация и протокол закрыт.
```

## Пример: протокол исправления бага (Таймаут сессии в auth)

### brief.md

```markdown
# Исправление: таймаут сессии (auth)

## Проблема

- Сессии истекают через 5 минут (ожидаемо: 30 минут).
- Влияние на пользователя: вынужденный повторный вход при обычном использовании.

## Критерии готовности (DoD)

- [ ] Длительность сессии установлена на 30 минут
- [ ] Добавлен регрессионный тест
- [ ] Покрытие остаётся 100%
```

### plan.md

```markdown
# План

## Шаги

- [ ] S1: Воспроизвести и найти конфиг сессии.
- [ ] S2: Исправить значение таймаута (минимальным изменением).
- [ ] S3: Добавить регрессионный тест (падает до фикса, проходит после).
- [ ] S4: Проверить тесты + покрытие 100% и закрыть протокол.

## Файлы к изменению

- `src/auth/session.ts`
- `tests/auth/session.test.ts`
```

### execution.md

```markdown
# Лог выполнения

- 2026-01-12: Исправлен конфиг и добавлен тест.
- 2026-01-12: Проверено 100% покрытие и протокол закрыт.
```
