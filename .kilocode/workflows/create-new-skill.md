# Создание нового навыка (create-new-skill)

## Назначение

Этот воркфлоу проводит агента через создание нового навыка (skill) для инфраструктуры `Skills`.
`Skills` - это переиспользуемые инструкции и процедуры для повторяемых задач или специализированных доменных областей.

## Когда использовать

Используй этот воркфлоу, когда:

- задача выявляет повторяющийся паттерн, который можно стандартизировать/автоматизировать
- разные протоколы снова и снова требуют одних и тех же шагов
- пользователь просит помощь в домене, где выгоднее иметь отдельный навык
- существующие навыки не покрывают текущие требования

## Шаги

### Шаг 1: Выявить повторяющийся паттерн

Перед созданием навыка зафиксируй повторяемость:

1. **Определи общий сценарий:** какая задача повторяется?

    - Пример: запуск тестов в разных проектах
    - Пример: безопасное выполнение CLI-команд
    - Пример: настройка окружения разработки

2. **Определи триггеры:** когда навык должен применяться?

    - какие формулировки запросов пользователя его вызывают
    - какие ситуации в проекте требуют этого навыка
    - какие протоколы выигрывают от стандартизации этого паттерна

3. **Разложи шаги:** что делается каждый раз одинаково?

    - выпиши шаги в порядке выполнения
    - выдели всегда одинаковые шаги
    - отметь, какие шаги зависят от контекста/стека

4. **Определи требуемый контекст:**
    - какие файлы Memory Bank нужно читать
    - какие файлы проекта нужно проверять
    - какая информация об окружении нужна (ОС, shell, CI, переменные окружения)

### Шаг 2: Спроектировать структуру навыка

Создай структуру SKILL.md так, чтобы её можно было применять повторно.

#### Обязательные разделы

**1) Назначение**

- что делает навык (1–3 предложения)
- зачем он существует
- какую боль закрывает

**2) Триггеры**

- список ситуаций, когда навык нужно применять
- типовые формулировки запросов
- сценарии протоколов, где навык особенно полезен

**3) Контекст**

- список файлов Memory Bank для чтения
- список файлов проекта для проверки
- любые дополнительные требования к контексту

**4) Процедура**

- пошаговая инструкция
- чёткие действия без двусмысленностей
- точки принятия решений и ветвления (если нужно)

#### Рекомендуемые разделы

**5) Лучшие практики**

- советы по эффективному применению
- типовые паттерны
- перформанс/стоимость (если релевантно)

**6) Диагностика и решения**

- частые проблемы и решения
- типовые ошибки и способы диагностики

**7) Интеграция с протоколами**

- как использовать навык внутри протокола
- что фиксировать в `plan.md`
- что логировать в `execution.md`
- когда обновлять Memory Bank

**8) Примеры**

- 1–2 реальных примера применения
- примеры команд/структуры файлов

### Шаг 3: Создать папку навыка и SKILL.md

Создай папку навыка и файл `SKILL.md`.

Базовый вариант (общий навык для всех режимов):

- каталог: `~/.kilocode/skills/`
- имя папки навыка: `SKILL_NAME`
- файл внутри папки: `SKILL.md`

Вариант для конкретного режима (mode-specific):

- в этом pack по умолчанию используем только общие навыки из `~/.kilocode/skills/`
- если нужно: используй отдельный каталог навыков для режима (паттерн `skills-{mode-slug}`) и положи туда папку `SKILL_NAME` с файлом `SKILL.md`

Важно:

- имя папки и поле `name` во frontmatter **должны совпадать** (kebab-case)

Шаблон:

```markdown
---
name: SKILL_NAME
description: [краткое описание в 1 строку]
---

# Навык: [Название навыка]

## Назначение

[Коротко: что делает навык и зачем]

## Триггеры

Используй этот навык, когда:

- [Триггер 1]
- [Триггер 2]
- [Триггер 3]

## Контекст

Перед применением прочитать:

- `.kilocode/memory-bank/FILE.md` - [зачем]
- `path/to/file.ext` - [зачем]

## Процедура

### Шаг 1: [Название шага]

[Инструкции]

### Шаг 2: [Название шага]

[Инструкции]

## Лучшие практики

- [Совет 1]
- [Совет 2]

## Диагностика и решения

### [Проблема 1]

[Описание и решение]

### [Проблема 2]

[Описание и решение]

## Интеграция с протоколами

Если навык используется в протоколе:

1. [Действие 1]
2. [Действие 2]
3. [Действие 3]

## Примеры

### Пример 1: [Название]

[Конкретный пример]
```

### Шаг 4: Обновить индексы навыков

Чтобы навык находился человеком и агентом, обнови индексы:

1. `~/.kilocode/skills/index.md` (навигация для людей)
2. `~/.kilocode/rules/skills-index.md` (правило/индекс для агента)

**Пример обновления:**

```markdown
## Доступные навыки

### Базовые навыки

- `project-tests/SKILL.md` - стандартизированный запуск тестов
- `cli-master/SKILL.md` - безопасная работа с CLI
- `SKILL_NAME/SKILL.md` - [краткое описание]

### Дополнительные навыки

[дополнительные навыки]
```

### Шаг 5: Проверить навык

Перед тем как считать навык готовым:

1. **Проверить ясность**: инструкции читаются без догадок?
2. **Проверить полноту**: все необходимые шаги описаны?
3. **Проверить точность**: команды и пути соответствуют реальности?
4. **Проверить интеграцию**: навык не конфликтует с workflows/правилами?

### Шаг 6: Задокументировать создание

Зафиксируй создание навыка в нужном месте:

1. **Если навык создан в рамках протокола** — допиши в `execution.md`.
2. **Если навык создавался отдельно** — заведи краткий протокол или запись в docs.
3. **Обнови Memory Bank**, если навык описывает важный устойчивый паттерн проекта.

## Чеклист качества навыка

- [ ] Назначение понятно с первой строки
- [ ] Триггеры достаточно конкретны
- [ ] Контекст перечислен явно
- [ ] Процедура полная и воспроизводимая
- [ ] Шаги выполняемые и без двусмысленностей
- [ ] Есть раздел "Лучшие практики" (если релевантно)
- [ ] Раздел "Диагностика и решения" покрывает частые сбои
- [ ] Есть примеры применения
- [ ] Описана интеграция с протоколами
- [ ] Индексы навыков обновлены
- [ ] Имя папки = `name` во frontmatter (kebab-case)
- [ ] Markdown оформлен корректно

## Примеры хороших навыков

### Пример 1: Навык миграций БД

Полезные элементы:

- назначение: стандартизировать апгрейды схемы
- триггеры: изменение схемы/миграций
- контекст: конфиги БД, миграции
- процедура: проверка версии -> миграция -> валидация/откат
- best practices: бэкап/стейджинг/порядок выполнения

### Пример 2: Навык генерации API-документации

Полезные элементы:

- назначение: единообразно документировать API
- триггеры: добавление/изменение эндпоинтов
- контекст: роуты, схемы, модели
- процедура: извлечь список эндпоинтов -> обновить документацию -> валидировать

## Частые ошибки

1. **Слишком общий навык** - трудно применить на практике

    - Плохо: "Сделай все операции с файлами"
    - Хорошо: "Безопасно удалить файлы с подтверждением и проверками"

2. **Слишком узкий навык** - почти не переиспользуется

    - Плохо: "Создать пользователя John/john@example.com"
    - Хорошо: "Создать пользователя с валидацией и обработкой ошибок"

3. **Нет контекста** — агент не знает, что читать/проверять

    - Всегда перечисляй Memory Bank и ключевые файлы проекта

4. **Нет примеров** — сложно понять ожидания

    - Всегда давай минимум один конкретный пример

5. **Неясные триггеры** - непонятно, когда применять
    - Сформулируй 3–7 чётких пунктов "когда использовать"

## Интеграция с существующими воркфлоу

Новые навыки должны сочетаться с:

- **Memory Bank**: читать релевантные файлы контекста
- **Протоколами**: фиксировать план/решения и не выходить за scope
- **Другими навыками**: дополнять, а не дублировать
- **Правилами проекта**: соблюдать ограничения и соглашения

## Непрерывное улучшение

После создания навыка:

1. Следить, насколько он помогает и где ломается
2. Собирать обратную связь (из протоколов/ревью)
3. Улучшать по реальным кейсам
4. При необходимости дробить/объединять навыки
5. Держать навык актуальным относительно эволюции проекта
