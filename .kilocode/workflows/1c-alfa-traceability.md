# 1C (firm): Трассируемость изменений (УЗ «База изменённых объектов» + XML) (1c-alfa-traceability)

## Назначение

Сделать изменения проверяемыми и релизопригодными за счёт корректного заполнения «Базы изменённых объектов» в УЗ.

## Источник (firm SoT)

- Обязательность фиксации изменений и рекомендации по XML: [`REG`](../sources/1c-alfa/reg.md#traceability)

## Входные данные

- `<TICKET>` (заявка УЗ/трекер)
- список изменяемых объектов (метаданные, модули, внешние обработки/отчёты)

## Правила (firm)

1. **Все изменения** должны быть зафиксированы в УЗ в таблице «База изменённых объектов».

    - Основание: [`REG`](../sources/1c-alfa/reg.md#traceability)

2. Из описания должно быть однозначно понятно:

- какой объект/участок кода изменён
- что именно добавлено/изменено
- новый объект или редактируется существующий
    - Основание: [`REG`](../sources/1c-alfa/reg.md#traceability)

3. Рекомендуется выгружать изменённые элементы в XML (через универсальную обработку) и прикреплять файл к заявке.

    - Основание: [`REG`](../sources/1c-alfa/reg.md#traceability)

4. Если изменения незначительные — допускается не выгружать XML, а описать изменения текстом/приложить текстовый файл.
    - Основание: [`REG`](../sources/1c-alfa/reg.md#traceability)

## Мини-чеклист заполнения «Базы изменённых объектов»

- [ ] Для каждого объекта: тип (метаданные/модуль/внешний отчёт/обработка), имя, что сделано
- [ ] Отметка «новый» vs «изменённый»
- [ ] Для релиза: учтены внешние команды/формулы/запросы параметров и т.п. (если применимо)

Основание: [`REG`](../sources/1c-alfa/reg.md#traceability)

## Гейт релиза

Релиз отменяется, если:

- база изменённых объектов не соответствует данным в хранилище
- или не пройден Code review

Основание: [`REG`](../sources/1c-alfa/reg.md#traceability)
