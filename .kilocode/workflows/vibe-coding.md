# Свободный режим разработки (`vibe-coding`)

`vibe coding` - режим для быстрого прототипирования и исследований, когда важнее скорость и поток, чем формальная документация.

В рамках WorkFlowAI этот режим допустим для исследовательских задач, но протокол обязателен всегда. `vibe coding` не отменяет протокол и не снимает гейты качества.

## Когда использовать

- Быстрое прототипирование (MVP, proof-of-concept).
- Исследование и эксперименты: найти подход, сравнить варианты, проверить гипотезу.
- Небольшие локальные утилиты и скрипты без изменения критичного поведения.

## Когда нужен подробный протокол

Если выполняется хотя бы один пункт, протокол должен быть детальным (полный план, матрица покрытия, риски).

- Меняется поведение/логика/публичный API.
- Затрагивается более 1 файла или добавляются новые файлы.
- Меняются зависимости, конфиги, CI/скрипты, миграции.
- Есть риски безопасности или данных.

## Минимальные артефакты (поверх протокола)

- Обязательные файлы протокола: `brief.md`, `plan.md`, `execution.md`.
- `CHECKLIST.md` в корне (лёгкий план "что сделать").
- Короткие заметки (в `CHECKLIST.md` или `temp/notes.md`): гипотезы, решения, что проверить.

## Процесс

1. Создай протокол (`brief.md`, `plan.md`, `execution.md`)
    - В `plan.md` можно сослаться на `CHECKLIST.md` для лёгкого плана.
2. Создай `CHECKLIST.md`
    - 5-15 пунктов, без больших вложенных эпиков.
3. Зафиксируй "что считаем готовым"
    - 2-5 критериев (например: "скрипт запускается", "линтер зелёный").
4. Сделай быстрый цикл
    - маленькие изменения
    - частые проверки (запуск, тесты, линт)
5. Финальная сверка
    - пройтись по чек-листу
    - сделать саморевью (качество/безопасность/долги)
6. Решение: оставаться в `vibe coding` или усилить протокол
    - `vibe coding` -> `строгий протокол`: когда растут риски или нужен полный формальный план
    - `строгий протокол` -> `vibe coding`: только если риски сняты и можно упростить план

## Связь с протоколом

| Аспект            | Протокол                       | `vibe coding` (в рамках протокола)        |
| ----------------- | ------------------------------ | ----------------------------------------- |
| Планирование      | `brief.md` + `plan.md`         | `brief.md` + `plan.md` + `CHECKLIST.md`   |
| Лог решений       | `execution.md`                 | `execution.md` + заметки в `CHECKLIST.md` |
| Контроль качества | 100% coverage, 0 lint warnings | те же гейты качества, без исключений      |
| Завершение        | ревью и мердж                  | саморевью + закрытие чек-листа + протокол |
