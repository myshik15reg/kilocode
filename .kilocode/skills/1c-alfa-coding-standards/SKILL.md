# Навык: 1C (firm) — Стандарты кода/метаданных

## Когда использовать

- Любое изменение кода/метаданных в 1С.

## Источники (firm SoT)

- Комментарии при модификации кода: [`REG`](../../sources/1c-alfa/reg.md#coding-standards-change-comments)
- Именование новых объектов метаданных (`ал_`): [`REG`](../../sources/1c-alfa/reg.md#coding-standards-prefixes)
- Устаревшие объекты (префикс «Удалить»): [`REG`](../../sources/1c-alfa/reg.md#coding-standards-prefixes)

## 1) Комментарии к изменениям (firm)

При модификации существующего кода использовать обязательную структуру:

```bsl
// + Альфа-Лизинг. <USER>. <DATETIME>. <TICKET>.
// Описание изменений
// Старый код (если был)
// - Альфа-Лизинг. <USER>. <DATETIME>.
```

Другой формат комментариев при модификации существующего кода не допускается.

Основание: [`REG`](../../sources/1c-alfa/reg.md#coding-standards-change-comments)

## 2) Префиксы для объектов метаданных (firm)

### Новые прикладные объекты

Формат: `ал_` + `ИмяОбъекта`.

Основание: [`REG`](../../sources/1c-alfa/reg.md#coding-standards-prefixes)

### Изменение объектов поставщика

При изменении состава объектов поставщика новые элементы префиксуются `ал_`.

Основание: [`REG`](../../sources/1c-alfa/reg.md#coding-standards-prefixes)

### Устаревшие объекты

Устаревшие объекты метаданных помечаются префиксом «Удалить».

Основание: [`REG`](../../sources/1c-alfa/reg.md#coding-standards-prefixes)

## 3) Документирование программного интерфейса (firm)

Процедуры и функции, входящие в программный интерфейс модулей, требуют обязательного комментирования (описание/параметры/возвращаемое/пример).

Основание: [`REG`](../../sources/1c-alfa/reg.md#coding-standards-api-doc)
