# Навык: 1C (firm) — Трассируемость изменений

## Когда использовать

- Любая задача, где меняются объекты конфигурации, внешние отчёты/обработки, тексты запросов и т.п.

## Источник (firm SoT)

- Раздел «Описание изменений по доработкам в учётной системе»: [`REG`](../../sources/1c-alfa/reg.md#traceability)

## Входные данные

- `<TICKET>`
- список изменённых объектов/участков кода

## Правила (firm)

1. Все изменения должны быть зафиксированы в УЗ в таблице «База изменённых объектов».

    - Основание: [`REG`](../../sources/1c-alfa/reg.md#traceability)

2. Описание должно однозначно указывать: что изменили и где.

    - Основание: [`REG`](../../sources/1c-alfa/reg.md#traceability)

3. Рекомендация: выгружать изменённые элементы в XML и прикреплять к `<TICKET>`.

    - Основание: [`REG`](../../sources/1c-alfa/reg.md#traceability)

4. Допускается не выгружать XML для незначительных изменений (описать текстом).
    - Основание: [`REG`](../../sources/1c-alfa/reg.md#traceability)

## Гейт релиза

Релиз по заявке отменяется, если база изменённых объектов не соответствует данным в хранилище или не пройден Code review.

Основание: [`REG`](../../sources/1c-alfa/reg.md#traceability)
