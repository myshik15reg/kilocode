# Навык: 1C (firm) — BPM / CRM (движок бизнес‑процессов)

## Когда использовать

- Разработка/изменение бизнес‑процессов в CRM.
- Добавление/настройка точек графической схемы.
- Настройка/сопровождение регламентных заданий бизнес‑процессов.

## Источник (firm SoT)

- Движок БП и точки: [`bpm.md`](../../sources/1c-alfa/bpm.md)

## Ключевые требования (firm)

### 1) Точка старта — уникальные идентификаторы

- Уникальное имя (без пробелов) и понятное наименование.

Основание:

- [`bpm.md#start-point`](../../sources/1c-alfa/bpm.md#start-point)

### 2) Точка условия / выбор варианта — обязательные обработчики

- Обработчик проверки условия обязателен.
- Обработчик выбора варианта обязателен.

Основание:

- [`bpm.md#condition-point`](../../sources/1c-alfa/bpm.md#condition-point)
- [`bpm.md#choice-point`](../../sources/1c-alfa/bpm.md#choice-point)

## Чеклист (что проверить)

### Конфигурация точек

- [ ] Для точки старта заполнены уникальное имя (без пробелов) и читаемое наименование.
- [ ] Для точки завершения заполнены уникальное имя (без пробелов) и читаемое наименование.
- [ ] Для точки условия настроен обработчик проверки условия; карта маршрута проходит проверку.
- [ ] Для точки выбора варианта настроен обработчик выбора варианта; каждый вариант настроен отдельно.

### Регламентные задания

- [ ] Для сценариев многократного выполнения учтено, что обработка использует отложенные задания.

## Evidence (как подтвердить)

- Скриншот/экспорт карты маршрута и результатов проверки перед сохранением (без персональных данных).
- Для точек условия/выбора: подтверждение наличия обработчиков (скриншот/CR запись).
- Для многократного выполнения: запись в `<TICKET>` о задействованных регламентных заданиях.
