# Навык: 1C (firm) — КД 3.0

## Когда использовать

- Любые изменения правил обмена в 1С: «Конвертация данных», ред. 3.0.

## Источники (firm SoT)

- Пайплайны выполнения (выгрузка/загрузка): [`KD3`](../../sources/1c-alfa/kd3.md#pipelines)
- Единое хранилище правил (КД3 как источник истины): [`KD3`](../../sources/1c-alfa/kd3.md#key-rules)
- Риск общих алгоритмов (не менять без уверенности): [`KD3`](../../sources/1c-alfa/kd3.md#key-rules)

## Ключевые правила (firm)

1. Все правила обмена должны быть перенесены в базу КД 3.0 (единое хранилище).

    - Основание: [`KD3`](../../sources/1c-alfa/kd3.md#key-rules)

2. Существующие правила не переименовывать.

    - Основание: [`KD3`](../../sources/1c-alfa/kd3.md#key-rules)

3. Алгоритмы общие для всех правил: не редактировать без уверенности, что изменения не повлияют на другие интеграции.
    - Основание: [`KD3`](../../sources/1c-alfa/kd3.md#key-rules)

## Firm-пайплайны выполнения (суть)

- Выгрузка: `КодПередВыполнениемЗапросов` → запросы → `КодПослеВыполненияЗапросов` → соответствие полей → соответствие таблиц → `КодПослеСозданияПакета`.

    - Основание: [`KD3`](../../sources/1c-alfa/kd3.md#pipelines)

- Загрузка: `КодПередОбработкойПакета` → `КодПередПолучениемОбъекта` → поиск → (создание ссылки) → `КодПослеПолученияОбъекта` → заполнение полей/таблиц → `КодПередЗаписьюОбъекта` → `КодПослеЗаписиОбъекта`.
    - Основание: [`KD3`](../../sources/1c-alfa/kd3.md#pipelines)
