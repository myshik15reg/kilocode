# Навык: 1C (firm) — RabbitMQ (интеграции)

## Когда использовать

- Любая задача, где затрагиваются RabbitMQ-обмены (настройка/разработка/сопровождение).
- Любая задача, где есть очереди, регламентные задания обработки/отправки сообщений.

## Источники (firm SoT)

- Детальные требования RabbitMQ и подсистемы отправки/получения: [`rabbitmq.md`](../../sources/1c-alfa/rabbitmq.md)
- Пакеты обмена (модель/ограничения): [`exchange-packet.md`](../../sources/1c-alfa/exchange-packet.md)

## Ключевые требования (firm)

### 1) vHost naming

- vHost по шаблону `<ENV>_<PROJECT>` (+ постфикс при необходимости).

Основание: [`rabbitmq.md#naming-vhost`](../../sources/1c-alfa/rabbitmq.md#naming-vhost)

### 2) HTTP API payload

- `payload` при отправке должен быть строкой.

Основание: [`rabbitmq.md#http-api`](../../sources/1c-alfa/rabbitmq.md#http-api)

### 3) Регламентные задания по очередям

- При необходимости — отдельные РЗ под конкретные очереди.

Основание: [`rabbitmq.md#scheduling-separate-jobs`](../../sources/1c-alfa/rabbitmq.md#scheduling-separate-jobs)

### 4) Отложенная отправка

- Рекомендуется использовать отложенную отправку, чтобы не отправлять сообщения из транзакции записи.

Основание: [`rabbitmq.md#subsystem-send-subscriptions`](../../sources/1c-alfa/rabbitmq.md#subsystem-send-subscriptions)

## Чеклист (что проверить)

### Проектирование / конфигурация

- [ ] Для каждой среды определён vHost по шаблону `<ENV>_<PROJECT>`.
- [ ] Для нагрузочных/критичных очередей предусмотрены отдельные регламентные задания.

### Контракты и отправка

- [ ] При отправке `payload` — строка.
- [ ] Если обмен идёт из записи объекта — используется отложенная отправка (или есть явное обоснование отказа).

### Подсистема 1С

- [ ] Объекты, формирующие пакеты обмена, подключены к подпискам отправки сообщений.
- [ ] Привязки «объект → РЗ» настроены через обработку «Настройка обмена сообщениями через очередь».

## Evidence (как подтвердить)

- Скриншоты/экспорты настроек РЗ и привязок очередей (без `<HOST>`/секретов).
- Фрагмент описания контракта/пример запроса с `payload` как строкой (санитизировано).
- Запись в `<TICKET>`: какие очереди/РЗ затронуты, что изменили.
