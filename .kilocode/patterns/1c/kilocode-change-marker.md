# Маркер изменений Альфа-Лизинг для BSL (1С)

## Назначение

Этот документ фиксирует **SoT (Source of Truth)** для маркировки изменений в коде BSL (1С) в формате **Альфа-Лизинг**.

Маркер изменений:

- ставится **обычным комментарием** `//` (не `///`),
- используется для трассировки правок и привязки к задаче (УЗ),
- оформляется **строго по шаблонам ниже**.

## SoT: обязательные шаблоны (Альфа-Лизинг)

### 1) Модификация кода (вставка/замена фрагмента) — обязательно блоком

```bsl
// + Альфа-Лизинг. АвторИзменений <?"", ДатаВремя, "ДФ='dd MMMM yyyy HH:mm'">. УЗ №НомерЗадачи.
//Описание изменений
//Старый код
// - Альфа-Лизинг. АвторИзменений <?"", ДатаВремя, "ДФ='dd MMMM yyyy HH:mm'">
```

**Эталонный пример (как вставлять рядом с заменой кода):**

```bsl
// + Альфа-Лизинг. АвторИзменений <?"", ДатаВремя, "ДФ='dd MMMM yyyy HH:mm'">. УЗ №26144.
//Исправлена проверка заполненности ИНН контрагента
//Если ПустаяСтрока(Контрагент.ИНН) Тогда
//    Возврат;
//КонецЕсли;

Если НЕ ЗначениеЗаполнено(Контрагент.ИНН) Тогда
    Возврат;
КонецЕсли;

// - Альфа-Лизинг. АвторИзменений <?"", ДатаВремя, "ДФ='dd MMMM yyyy HH:mm'">
```

### 2) Автор метода (шапка перед методом/описанием)

```bsl
// Альфа-Лизинг. АвторИзменений <?"", ДатаВремя, "ДФ='dd MMMM yyyy HH:mm'">. УЗ №НомерЗадачи.
```

**Эталонный пример:**

```bsl
// Альфа-Лизинг. АвторИзменений <?"", ДатаВремя, "ДФ='dd MMMM yyyy HH:mm'">. УЗ №26144.
Процедура ал_ПроверитьИНН(Контрагент) Экспорт
    // ...
КонецПроцедуры
```

### 3) Новый объект метаданных 1С (в комментарии объекта)

Шаблон (строго как строка в комментарии объекта):

```
АвторИзменений / <?"", ДатаВремя, "ДФ='dd MMMM yyyy'"> / УЗ НомерЗадачи
```

**Эталонный пример:**

```
Фоменко Д.С. / 01.04.2025 / УЗ 26144
```

## Где ставить маркер

- Для замены/вставки фрагмента — ставь блок **вплотную** к месту изменения.
- Для авторства метода — ставь строку **непосредственно над** процедурой/функцией.
- Для нового объекта метаданных — строка помещается в **комментарий объекта**.

## Совместимость со старыми маркерами (legacy)

В истории репозитория могут встречаться старые маркеры (например, `// kilocode_change: [...] ...`).

Это **нормально для истории**: массово переписывать такие маркеры не требуется.

Правило для новых правок в BSL: **SoT — только формат Альфа-Лизинг из раздела выше.**

## Связь с jdocstring

jdocstring использует `///` и предназначен для документирования API (описание, параметры, примеры и т.д.).

Маркер изменений Альфа-Лизинг оформляй как обычный комментарий `//`, чтобы не смешивать техническую трассировку с docstring.

См. также: [`jdocstring.md`](jdocstring.md).
