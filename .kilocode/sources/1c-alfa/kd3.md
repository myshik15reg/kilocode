# KD3 — регламент доработки и CR правил КД 3.0 (firm): операционная выжимка

Это **не** копия первичного документа. Это санитизированная выжимка правил, используемых в pack как firm‑SoT.

Плейсхолдеры:

- `<TICKET>` — номер заявки/тикета.

---

<a id="key-rules"></a>

## Ключевые правила (firm)

1. **Единое хранилище правил** — база 1С «Конвертация данных», ред. 3.0. Изменения нужно переносить в КД 3.0.
2. **Существующие правила не переименовывать** (в отдельных интеграциях может использоваться поиск по имени правила).
3. **Общие алгоритмы** для всех правил: не редактировать без уверенности, что изменения не повлияют на другие интеграции.
4. Изменения программного кода правил вносить с учётом общего регламента разработки 1С (оформление модулей/запросов/комментариев и т.п.).

---

<a id="pipelines"></a>

## Firm‑пайплайны выполнения

### Выгрузка: порядок этапов формирования пакета

1. `КодПередВыполнениемЗапросов`
2. выполнение запросов
3. `КодПослеВыполненияЗапросов`
4. заполнение пакета по соответствию полей
5. заполнение пакета по соответствию таблиц
6. `КодПослеСозданияПакета`

### Загрузка: порядок этапов обработки пакета

1. `КодПередОбработкойПакета`
2. `КодПередПолучениемОбъекта`
3. поиск объекта (GUID / доп. поиск)
4. определение ссылки нового объекта (если не найден)
5. `КодПослеПолученияОбъекта`
6. заполнение полей (соответствие полей)
7. заполнение таблиц (соответствие таблиц)
8. `КодПередЗаписьюОбъекта`
9. `КодПослеЗаписиОбъекта`

<a id="process"></a>

## Минимальный процесс доработки (firm)

1. Определи направление интеграции и затрагиваемый объект/пакет.
2. Внеси изменения в правило, учитывая firm‑пайплайны выполнения.
3. Зафиксируй изменения в УЗ по `<TICKET>` (раздел «Изменённые объекты»/трассируемость).
4. Проведи тестирование и Code Review.
5. Перенеси правила в продуктивные системы установленным способом.
