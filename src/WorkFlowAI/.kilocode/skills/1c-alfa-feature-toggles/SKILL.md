# Навык: 1C (firm) — Отключаемый функционал / очистка легаси

## Когда использовать
- Добавление «отключаемого функционала» (feature toggle).
- Завершение работ по заявке, когда требуется очистка старого функционала.

## Источник (firm SoT)
- Feature toggles + очистка легаси: [`feature-toggles.md`](../../sources/1c-alfa/feature-toggles.md)

## Ключевые требования (firm)

### 1) Привязка к заявке
- При использовании механизма требуется указывать `<TICKET>` (без лидирующих нулей) и корректно задавать активацию по умолчанию.

Основание:
- [`feature-toggles.md#toggle-purpose`](../../sources/1c-alfa/feature-toggles.md#toggle-purpose)

### 2) Очистка старого функционала после релиза
- После релиза заявки в CRM требуется установить признак «Старый функционал очищен».

Основание:
- [`feature-toggles.md#legacy-cleanup`](../../sources/1c-alfa/feature-toggles.md#legacy-cleanup)

## Чеклист (что проверить)
- [ ] Для feature toggle указан `<TICKET>` (без лидирующих нулей).
- [ ] Параметр активации по умолчанию согласован с требуемым поведением после релиза.
- [ ] После релиза: признак «Старый функционал очищен» установлен.
- [ ] При постановке техдолга на очистку легаси включено требование использовать «Поиск кода в данных».

## Evidence (как подтвердить)
- Скриншот элемента справочника «Отключаемый функционал» (без данных окружения).
- Ссылка на `<TICKET>` с отметкой о выполнении очистки.
