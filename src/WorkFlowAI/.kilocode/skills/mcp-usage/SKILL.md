# MCP Usage

Use this skill when MCP resources or tools are available and may help answer or execute the task.

## Core rules

1. Prefer the smallest useful MCP query.
2. Use MCP when it gives better or more direct context than blind repository searching.
3. Do not overfetch resources that the current task does not need.
4. Keep the result tied to the actual decision or action being taken.

## Good use cases

- structured project metadata
- resource catalogs or context providers
- targeted schema or system information
- environment-specific context that is hard to infer from files alone

## Anti-patterns

- loading everything because it is available
- treating MCP as mandatory for simple local tasks
- pasting large MCP outputs without summarizing relevance
