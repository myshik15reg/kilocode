# 1C (firm): Доработка/CR правил КД 3.0 (1c-alfa-kd3)

## Назначение
Дать firm-ориентированный чеклист/порядок работы с правилами обмена в 1С: «Конвертация данных», ред. 3.0.

## Источник (firm SoT)
- Пайплайны выполнения при выгрузке/загрузке: [`KD3`](../sources/1c-alfa/kd3.md#pipelines)

## Ключевые правила (firm)
1) Единым хранилищем всех правил обмена является база КД 3.0; изменения нужно переносить в КД 3.0.
   - Основание: [`KD3`](../sources/1c-alfa/kd3.md#key-rules)

2) Наименование существующих правил менять нельзя (может использоваться поиск по имени).
   - Основание: [`KD3`](../sources/1c-alfa/kd3.md#key-rules)

## Firm-SOT пайплайны выполнения

### Выгрузка: порядок этапов формирования пакета
1. `КодПередВыполнениемЗапросов`
2. выполнение запросов
3. `КодПослеВыполненияЗапросов`
4. заполнение пакета по соответствию полей
5. заполнение пакета по соответствию таблиц
6. `КодПослеСозданияПакета`

Основание: [`KD3`](../sources/1c-alfa/kd3.md#pipelines)

### Загрузка: порядок этапов обработки пакета
1. `КодПередОбработкойПакета`
2. `КодПередПолучениемОбъекта`
3. поиск объекта (GUID / доп. поиск)
4. определение ссылки нового объекта (если не найден)
5. `КодПослеПолученияОбъекта`
6. заполнение полей (соответствие полей)
7. заполнение таблиц (соответствие таблиц)
8. `КодПередЗаписьюОбъекта`
9. `КодПослеЗаписиОбъекта`

Основание: [`KD3`](../sources/1c-alfa/kd3.md#pipelines)

---

## Процесс доработки (минимум)
1) Определи направление интеграции и затрагиваемый объект/пакет.
2) Внеси изменения в правило, учитывая firm-пайплайны (выше).
3) Зафиксируй изменения в УЗ по `<TICKET>` (раздел «Измененные объекты»).
4) Проведи тестирование и Code Review.
5) Перенеси правила в продуктивные системы установленным способом.

Основание переноса в продуктив после тестирования и CR: [`KD3`](../sources/1c-alfa/kd3.md#process)
