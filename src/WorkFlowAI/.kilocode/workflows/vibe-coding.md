# Workflow: vibe-coding

## Goal

Allow a lighter-weight implementation rhythm for low-risk work while still respecting core protocol, verification, and scope rules.

## Use when

- the task is exploratory but still bounded
- a lightweight checklist is enough to keep the work safe
- full heavyweight planning would add more overhead than value

## Core rules

1. This is not a waiver from protocol discipline for real repo changes.
2. Keep a short, explicit checklist or plan.
3. Verify frequently in small increments.
4. Escalate to a stricter workflow if risk or scope grows.

## Good fit

- small iterative cleanups
- bounded experimentation
- low-risk polishing with clear rollback or verification

## Bad fit

- high-risk production fixes
- deep migrations
- security-sensitive or architecture-heavy work
