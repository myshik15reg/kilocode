# Workflow: protocol examples

## Goal

Show small examples of how a protocol is structured without turning examples into the source of truth.

## Use this file for

- understanding the expected shape of `brief.md`, `plan.md`, and optional notes
- giving maintainers or agents a quick mental model of a good protocol

## Example expectations

A good protocol usually includes:

- one clear goal
- explicit scope and constraints
- ordered steps with verification
- only the evidence needed for the task

## Important rule

Examples are illustrative only.
The canonical lifecycle is defined by [`protocol-new.md`](protocol-new.md:1), [`protocol-resume.md`](protocol-resume.md:1), and [`protocol-review-merge.md`](protocol-review-merge.md:1).
