# Отключаемый функционал и очистка легаси (firm)

Это **не** копия первичных документов. Это санитизированная выжимка требований по отключаемому функционалу (feature toggles) и процессу очистки старого функционала.

Плейсхолдеры:
- `<TICKET>` — номер заявки/тикета.

<a id="toggle-purpose"></a>
## Отключаемый функционал (MUST)

**MUST:** Механизм рекомендуется использовать, когда нужно иметь возможность отключать участок кода из режима предприятия без динамических обновлений, а также как альтернативу константам/предопределённым значениям, если это уместно.

Источник:
- `Отключаемый+функционал.doc`

**MUST:** При использовании функции необходимо:
- в первый параметр передать строкой номер заявки из УЗ (`<TICKET>`, без лидирующих нулей);
- второй параметр — активация по умолчанию (Истина/Ложь).
  - если не заполнено или Ложь — функционал не будет активен после релиза;
  - если Истина — функционал активируется автоматически.

Источник:
- `Отключаемый+функционал.doc`

---

<a id="legacy-cleanup"></a>
## Очистка старого функционала (MUST)

**MUST:** После релиза заявки в CRM необходимо установить признак «Старый функционал очищен» у соответствующего элемента справочника «Отключаемый функционал».

Источник:
- `Концепция+очистки+старого+функционала.doc`

**MUST:** В шаблон описания создаваемой заявки на техдолг по очистке старого функционала нужно добавить напоминание: анализировать код не только внутри конфигурации, но также обязательно выполнять поиск с использованием обработки «Поиск кода в данных».

Источник:
- `Концепция+очистки+старого+функционала.doc`
