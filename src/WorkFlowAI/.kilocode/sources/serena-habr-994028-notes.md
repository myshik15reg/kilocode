# Serena/MCP — конспект по статье Habr (ID 994028)

> Источник: https://habr.com/ru/articles/994028/
>
> Примечание: полный текст статьи в этой сессии не загружался (сетевые ограничения).
> Конспект составлен по извлечённым фрагментам из выдачи поиска MCP Perplexity.
> Используйте это как «starter» для ADR/decision memo и уточните формулировки при локальном доступе к статье.

## 1) Позиционирование Serena

- Serena описана как MCP-сервер, который берёт на себя:
  - «память проекта» (чтение/запись заметок, чтобы переживать смену контекстного окна/агента)
  - поиск по проекту и точечные правки «вне контекстного окна» IDE, чтобы экономить токены.

## 2) Инструменты “памяти проекта” (упомянутые в статье)

В статье приведены инструменты (названия как в примере):
- `read_memory()`
- `edit_memory()`
- `delete_memory()`
- `list_memories()`
- `write_memory()`

Утверждение из статьи (по фрагменту): память особенно полезна при смене контекстного окна в IDE или смене агента — новый агент «ничего не знает о проекте», и Serena позволяет быстро ознакомиться с контекстом.

## 3) Токены и кэш

- В статье подчёркнуто, что в подсчёте токенов учитывается кэш IDE (пример — Cursor): даже “закешированное” остаётся платным.
- Приведён пример/оценка экономии токенов на задаче доработки большой конфигурации (ЗУП 3.1):
  - без Serena — ~3 млн токенов,
  - с Serena — ~1.6 млн токенов.

## 4) BSL/1C форк (serena+bsl)

- Указано, что за основу взят проект Serena `oraios/serena`.
- Для 1С заявлена поддержка языка 1С (BSL) через форк (в статье упоминается как “serena+bsl”).
- Для BSL описан отдельный механизм построения дерева процедурных вызовов и их зависимостей.

## 5) Кэш и структура данных (BSL)

- Указано расположение кэша: `.serena\\cache\\bsl`.
- Если в настройках Serena установить `log_level: 10`, можно увидеть, как читаются модули и как строится кэш.
- При инициализации Serena кэш вызовов проверяется по fingerprint; если модуль изменился — кэш автоматически обновляется.
- Для ускорения кэш и карта процедурных вызовов загружаются в оперативную память.

## 6) Практика “как писать код” (фрагмент из статьи)

По фрагменту из статьи упоминается практический порядок действий:
- при разборе проекта — использовать MCP Serena;
- после правок BSL — запускать syntax check (в примере упомянут отдельный MCP "syntax-checker").
