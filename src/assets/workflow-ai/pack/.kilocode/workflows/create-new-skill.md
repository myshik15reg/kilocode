# Workflow: create-new-skill

## Goal

Create a reusable skill only when a task pattern is repeated often enough to justify a dedicated instruction pack.

## Create a skill when

- the same process repeats across multiple tasks
- the pattern needs stable steps, boundaries, or references
- existing skills do not cover the need cleanly

## Do not create a skill when

- the need is one-off or highly local
- a workflow or rule update would solve the problem better
- the pattern is still too vague to standardize

## Recommended flow

| Step | Outcome                                           |
| ---- | ------------------------------------------------- |
| 1    | identify the repeated task pattern                |
| 2    | define triggers for when the skill should be used |
| 3    | capture the stable steps and boundaries           |
| 4    | add only the references truly needed              |
| 5    | keep the skill portable and concise               |

## Good skill contents

- what the skill is for
- when to use it
- the minimal reliable process
- key pitfalls or boundaries
- specific references or scripts only when necessary

## Anti-patterns

- turning a one-off note into a permanent skill
- copying huge reference material into `SKILL.md`
- baking project history into a reusable skill
- creating a skill where a small rule or workflow edit is enough
