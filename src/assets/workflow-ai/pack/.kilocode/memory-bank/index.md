# Memory Bank

> **Единый источник истины** для контекста проекта.

## Быстрый старт (Level 1)

```
1. Читай ТОЛЬКО context.md для текущего фокуса
2. Остальные файлы — по необходимости
3. Подтверди: [MB: OK]
```

**НЕ читай всё!** См. [`.kilocode/rules/context-tiers.md`](../rules/context-tiers.md)

## Файлы
| Файл | Назначение | Когда обновлять |
|------|------------|-----------------|
| [`brief.md`](brief.md) | Цели, ограничения, DoD | При изменении целей/DoD |
| [`product.md`](product.md) | Пользователи, ценность, UX | При изменении продукта/UX |
| [`architecture.md`](architecture.md) | Архитектурные решения | После архитектурных изменений |
| [`tech.md`](tech.md) | Стек и инструменты | При изменении стека |
| [`context.md`](context.md) | Текущий фокус, риски, next steps | Регулярно |

## Метаданные (заполни при старте проекта)
- **Project:** WorkFlowAI
- **Phase:** Оптимизация документации / сопровождение
- **Last Updated:** 2026-01-28

## Правила использования
- Обновляй Memory Bank после значимых изменений.
- Детали конкретных задач — только в `.protocols/YYYY-MM-DD-name/`.
- Держи тексты короткими и фактологичными.

> Примечание про пути: pack может работать в двух режимах.
> - **Embedded (в репозитории):** основные файлы лежат в `.kilocode/`.
> - **Global install:** файлы пакета установлены в `~/.kilocode/` (домашняя директория пользователя).
> В этом репозитории в примерах используется путь `.kilocode/`.

## Когда обновлять какой файл (подробнее)

### brief.md — Обновляй при изменении ЦЕЛЕЙ

| Событие | Действие |
|---------|----------|
| Изменились бизнес-цели проекта | Обновить раздел «Цели» |
| Добавились/убрались ограничения | Обновить раздел «Ограничения» |
| Изменился Definition of Done | Обновить раздел DoD |
| Новый стейкхолдер | Добавить в список стейкхолдеров |

**НЕ обновляй при:** рутинной разработке, исправлениях багов и небольших фичах.

### product.md — Обновляй при изменении ПРОДУКТА

| Событие | Действие |
|---------|----------|
| Новый тип пользователя | Обновить описания пользователей |
| Изменился UX-flow | Обновить пользовательские сценарии |
| Новая ключевая фича | Добавить в ключевые возможности |
| Pivot или крупное изменение | Полный пересмотр |

**НЕ обновляй при:** внутреннем рефакторинге и изменениях бэкенда, которые не видны пользователю.

### architecture.md — Обновляй при АРХИТЕКТУРНЫХ изменениях

| Событие | Действие |
|---------|----------|
| Новый сервис/модуль | Добавить в раздел компонентов |
| Изменение базы данных | Обновить модель данных |
| Новая интеграция | Добавить в раздел интеграций |
| Архитектурное решение (ADR) | Добавить в раздел решений |
| Смена паттерна (monolith -> microservices) | Полный пересмотр |

**НЕ обновляй при:** деталях реализации внутри существующих компонентов.

### tech.md — Обновляй при изменении СТЕКА

| Событие | Действие |
|---------|----------|
| Добавлена новая библиотека (major) | Добавить в зависимости |
| Смена фреймворка | Обновить Stack |
| Новый инструмент разработки | Добавить в инструменты |
| Обновление major версии | Обновить версии |

**НЕ обновляй при:** обновлениях патч-версий и зависимостях, используемых только для разработки.

### context.md — Обновляй РЕГУЛЯРНО

| Событие | Действие |
|---------|----------|
| Закрыт протокол | Обновить "Что достигли" |
| Начат новый протокол | Обновить "Текущий фокус" |
| Выявлен риск | Добавить в Risks |
| Решение блокера | Убрать из Blockers |
| Планирование итерации | Обновить Next Steps |

**Рекомендация:** Обновлять context.md при каждом закрытии/открытии протокола.

## Чеклист после закрытия протокола

После закрытия каждого протокола проверь:

- [ ] **context.md** — Обновлён текущий фокус и next steps?
- [ ] **architecture.md** — Были ли архитектурные изменения?
- [ ] **tech.md** — Добавлены ли новые зависимости?
- [ ] **brief.md** — Изменились ли цели или DoD?
- [ ] **product.md** — Изменился ли продукт для пользователя?
