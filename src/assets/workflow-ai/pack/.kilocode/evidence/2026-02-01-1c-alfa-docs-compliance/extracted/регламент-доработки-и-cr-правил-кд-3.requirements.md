- [SHOULD] Важно: единым хранилищем всех правил обмена является база 1С: «Конвертация данных», редакция 3.0 (путь к ней указан в статье по ссылке в п.6 раздела «Полезные ссылки», база «Конфигурация пакетов»). Поэтому следует не забывать переносить изменения в КД 3.0. Для этого в «Редакторе правил» предусмотрены режимы загрузки и выгрузки правил через файлы. (section: )
- [SHOULD] При разработке правил следует помнить последовательность выполнения этих этапов. (section: )
- [MUST] Каждый элемент справочника «Наборы правил» должен содержать правила, относящиеся к конкретному обмену, для обработки входящего пакета (при загрузке) и формирования исходящего пакета (при выгрузке). Например, при выгрузке договорной базы помимо правил обмена договорами лизинга, поставки, в этом же наборе должны находиться правила выгрузки организаций, контрагентов, номенклатуры, лизинговых расчетов и т.п. (section: )
- [MUST] Наименование набора правил должно содержать направление интеграции (например, CRM_ERP означает, что данные будут выгружены из CRM и загружены в ERP) и отражать суть интеграции (например, Выгрузка договорной базы, Выгрузка возвратов по ДКП). (section: )
- [SHOULD] В поле «Конфигурация обмена» следует указывать конфигурацию базы 1С, для которой разрабатываются правила. (section: )
- [MUST] Наименование правила должно содержать направление интеграции (например, CRM_ERP, означает, что данные будут выгружены из CRM и загружены в ERP) и наименование передаваемого объекта (например, Выгрузка договора лизинга, Выгрузка лизингового расчета). (section: )
- [MUST] Важно: наименование существующих правил менять нельзя, т.к. в некоторых интеграциях поиск правила осуществляется по его имени. (section: )
- [MUST] При выгрузке источник может соответствовать физическому объекту метаданных конфигурации-источника, а может являться виртуальным объектом. Например, «СправочникСсылка.ДоговорыКонтрагентов», «блЛизинговыйРасчет_Виртуальный». В случае виртуального источника перед выгрузкой необходимо определить структуру с ключом «ИмяИсточника»: (section: )
- [MUST] В поле «Отбор» (Рисунок 4) вносится исполняемый в функции «Вычислить» код, обеспечивающий фильтрацию правил, подобранных для объекта метаданных. Результатом функции должно быть булево. (section: )
- [MUST] В режиме выгрузки доступны поля «Обмен» и «Ключ маршрутизации» (Рисунок 4), которые должны быть заполнены для отправки пакета на основе настроек очередей Rabbit MQ. (section: )
- [MUST] В поле «Отбор» вносится исполняемый в функции «Вычислить» код, обеспечивающий фильтрацию правил, подобранных для объекта метаданных. Результатом функции должно быть булево. (section: )
- [MUST] В режиме загрузки доступно поле «Очередь», которое должно содержать наименование очереди, как оно задано в Rabbit MQ. Содержит имя очереди, к пакетам из которой применимо данное правило. (section: )
- [MUST] Наименования полей должны отражать их суть. При выгрузке значения уникального идентификатора следует задавать имя полю «UID», а не «GUID». «GUID» – только если выгружается значение общего реквизита «GUID». (section: )
- [SHOULD] С целью уменьшения числа ошибок при описании соответствия полей следует использовать команду «Заполнить по полям приемника», либо кнопку выбора напротив соответствующего поля. (section: )
- [MUST] Для таблиц пакета обмена в поле «Выражение» необходимо указывать из результата какого запроса типа «Заполнение таблиц» необходимо брать данные: (section: )
- [SHOULD] Во второй табличной части закладки доступно обращение к структуре запроса «ВыборкаТаблицы». С целью уменьшения числа ошибок при описании соответствия полей следует использовать команду «Заполнить подчиненные реквизиты ТЧ», либо кнопку выбора напротив соответствующего поля. (section: )
- [MUST] Важно: не следует выносить в правило логику, касающуюся создания объектов на основе загружаемого объекта, отправку писем и т.п. Данная логика должна быть описана в методах конфигурации. (section: )
- [MUST] Если в программном коде используется обращение к запросам данного правила, необходимо следить что запрос не будет выполняться в цикле. (section: )
- [SHOULD] Важно: алгоритмы являются общими для всех правил. Один и тот же алгоритм может использоваться в разных правилах. Не следует редактировать алгоритм, если нет уверенности, что его изменение не повлияет на другие интеграции. (section: )
- [MUST] На закладке «Соответствие полей» для каждого поля, для которого необходимо получить значение из запроса, указывается в соответствие имя поля из запроса типа «Заполнение полей». (section: )
- [MUST] Для каждой таблицы пакета обмена указывается из результата какого запроса типа «Заполнение таблиц» необходимо брать данные. (section: )
- [MUST] Поле «Параметры» предназначено для справочного отображения списка входящих и исходящих параметров, которые должны быть проинициализированы до вызова алгоритма. (section: )
- [SHOULD] Важно: алгоритмы являются общими для всех правил. Один и тот же алгоритм может использоваться в разных правилах. Не следует редактировать алгоритм, если нет уверенности, что его изменение не повлияет на другие интеграции. (section: )
- [MUST] На вкладке «Поля запроса» должны быть выбраны все поля, которые будут доступны для выбора в правиле на закладке «Соответствие полей». С целью уменьшения числа ошибок при заполнении полей следует использовать команду «Заполнить из запроса». (section: )
- [MUST] На вкладке «Параметры запроса» должны быть выбраны параметры, которые необходимо заполнить в правиле. С целью уменьшения числа ошибок при заполнении параметров следует использовать команду «Заполнить из запроса». (section: )
- [MUST] При заполнении в УЗ информации об измененных объектах необходимо выбрать подходящий элемент (например, при выгрузке данных из CRM в ERP, необходимо выбирать элемент «CRM_ERP»). Далее выбрать элемент, в случае редактирования уже существующего правила (Рисунок 34), или создать новый, в случае описания нового обмена. (section: )

- [MUST] Процедура инспекции кода для проверяющего ничем не отличается от проведения CR в любой другой системе на базе 1С. Все изменения, внесенные в программный код правил, должны соответствовать регламенту разработки систем на платформе 1С: Предприятие 8.3 ГК «Альфа-Лизинг». (section: )

- [MUST] наименования правил и наборов правил должны содержать направление интеграции (например, CRM_ERP означает, что данные будут выгружены из CRM и загружены в ERP) и отражать суть интеграции (например, Выгрузка договорной базы, Выгрузка возвратов по ДКП); (section: )
- [MUST] наименования очередей и ключей маршрутизации должны соответствовать шаблону, приведенному в статье из п.1 раздела «Полезные ссылки»; (section: )

- [MUST] На закладке «Основное» обратить внимание на реквизит «Отбор». В данном поле содержится программный код, который выполняется в функции «Вычислить». Результатом функции должно быть булево. (section: )
- [MUST] На закладке «Соответствие полей» обратить внимание на реквизит «Выражение». В данном поле содержится программный код, который выполняется в функции «Вычислить» для простого выражения и «Выполнить» для строки с установленным флагом «Сложное выражение». Если в выражении описывается обращение к алгоритму, то необходимо проверить включен ли он в состав алгоритмов правила на закладке «Алгоритмы». У свойства заголовка может быть любое имя, значение всегда типа строка. (section: )
