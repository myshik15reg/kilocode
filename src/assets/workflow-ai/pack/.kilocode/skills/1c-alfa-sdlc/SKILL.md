# Навык: 1C (firm) — SDLC «Заявка → DONE»

## Когда использовать

- Любая задача по 1С, где есть изменения кода/метаданных/форм.
- Любая задача, которая должна пройти через тестирование, CR, релиз.

## Источник (firm SoT)

- Этапы SDLC: [`REG`](../../sources/1c-alfa/reg.md#sdlc)

## Ключевые правила (firm)

### 1) Классификация задач

- Поддержка: оценка кодирования < 1 часа.
- Проектная: оценка кодирования > 1 часа.

Основание: [`REG`](../../sources/1c-alfa/reg.md#sdlc-task-classification)

### 2) Гейт разработки: «База изменённых объектов»

Все изменения объектов и функционала должны быть описаны разработчиком в «Базе изменённых объектов» заявки.

Основание: [`REG`](../../sources/1c-alfa/reg.md#sdlc-development-gate-changed-objects)

### 3) Гейт тестирования: ИТ + бизнес + письменное подтверждение

Этап тестирования включает:

- «ИТ-тестирование»
- «Бизнес-тестирование» заказчиком/представителем

После тестирования заказчик письменно подтверждает корректную работу функционала или возвращает на доработку.

Основание: [`REG`](../../sources/1c-alfa/reg.md#sdlc-testing-gate)

### 4) Гейт релиза: CR обязателен

Перенос в продуктив выполняется только после успешного прохождения Code review.

Основание: [`REG`](../../sources/1c-alfa/reg.md#sdlc-release-gate-code-review)

## Минимальный процесс применения

1. На входе зафиксируй `<TICKET>` и класс задачи (поддержка/проект).
2. Для проектных задач проверь наличие артефактов «Аналитика/Архитектура» (согласования/сценарии/Design review).
3. Перед передачей в релиз убедись, что:
    - заполнена «База изменённых объектов»
    - выполнены ИТ‑тестирование и бизнес‑тестирование
    - есть письменное подтверждение заказчика
    - пройден Code review
