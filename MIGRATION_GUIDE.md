# Руководство по миграции на гибридный поиск

С последним обновлением мы представляем гибридный поиск, который объединяет мощь семантического поиска (Qdrant) и структурного анализа кода (Neo4j). Это обеспечивает более точные и контекстно-зависимые результаты.

## Нужно ли мне что-то делать?

Если у вас уже есть существующий индекс кодовой базы, созданный в предыдущей версии, **да, вам необходимо выполнить полную переиндексацию**, чтобы воспользоваться преимуществами новой системы. Старые индексы, содержащие только векторные данные, несовместимы с гибридным поиском.

## Шаги по миграции

### Шаг 1: Настройка Neo4j

Перед переиндексацией убедитесь, что у вас запущен и настроен экземпляр Neo4j. Самый простой способ — использовать предоставленный `docker-compose.yml`.

1.  Установите Docker, если он у вас не установлен.
2.  В корне проекта выполните команду:
    ```bash
    docker-compose up -d
    ```
3.  Это запустит контейнеры Qdrant и Neo4j. Учетные данные для Neo4j по умолчанию: `neo4j/kilocode123`.

### Шаг 2: Удаление старого индекса

Чтобы избежать конфликтов, рекомендуется удалить старый индекс перед созданием нового.

1.  Откройте настройки индексации.
2.  Нажмите кнопку "Удалить индекс" (Delete Index).

### Шаг 3: Полная переиндексация

Теперь вы готовы к созданию нового гибридного индекса.

1.  В настройках индексации убедитесь, что все параметры (включая подключение к Neo4j) указаны верно.
2.  Нажмите кнопку "Создать и проиндексировать кодовую базу" (Create & Index Codebase).
3.  Дождитесь завершения процесса. Теперь у вас есть полнофункциональный гибридный индекс.
