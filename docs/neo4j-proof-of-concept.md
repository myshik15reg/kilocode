## Введение

Этот документ предоставляет пошаговое руководство для демонстрации возможностей Neo4j интеграции в AlfaCode assistant. Вы сможете увидеть реальные преимущества гибридного поиска, который сочетает:

- **Semantic Search (Qdrant)**: Поиск по смыслу кода
- **Graph Navigation (Neo4j)**: Навигация по структуре и зависимостям

## Подготовка

### Требования

1. **Neo4j** запущен и доступен по `bolt://localhost:7687`
2. **Qdrant** запущен и доступен по `http://localhost:6333`
3. **AlfaCode assistant** установлен и настроен

### Проверка системы

Проверьте, что все компоненты работают:

```bash
# Проверка Qdrant
cd src
npm run check:qdrant

# Проверка Neo4j
# Откройте браузер: http://localhost:7474
# Выполните запрос:
MATCH (n) RETURN count(n) as node_count
```

### Подготовка тестового проекта

Для наилучшей демонстрации используйте проект со следующими характеристиками:

- **Размер**: минимум 50+ файлов
- **Сложность**: несколько модулей/пакетов
- **Зависимости**: перекрестные ссылки между файлами
- **Язык**: TypeScript, JavaScript, Python или другой поддерживаемый

Пример: сам проект AlfaCode assistant идеально подходит для демонстрации.

### Индексация кодовой базы

1. Откройте проект в VS Code
2. Запустите индексацию через AlfaCode assistant:
    - Откройте панель AlfaCode assistant
    - Используйте команду для индексации кодовой базы
    - Дождитесь завершения (обычно 2-5 минут для среднего проекта)

Проверьте, что индексация завершена:

```bash
npm run check:qdrant
# Должно показать количество проиндексированных векторов
```

## Сценарий 1: Базовый Hybrid Search

### Цель

Продемонстрировать преимущества комбинированного поиска по смыслу и структуре.

### Шаги

1. **Откройте AlfaCode assistant** и переключитесь в режим "Ask"

2. **Задайте вопрос на естественном языке:**

    ```
    Как реализована аутентификация пользователя?
    ```

3. **Наблюдайте результаты:**

    **С Neo4j (Hybrid Search):**

    - ✅ Найдены файлы с кодом аутентификации (Qdrant)
    - ✅ Показаны связанные модули: session management, token validation (Neo4j)
    - ✅ Выявлены зависимости: middleware, database models (Neo4j)
    - ✅ Структурированный ответ с учетом архитектуры

    **Без Neo4j (только Qdrant):**

    - ✅ Найдены файлы с кодом аутентификации
    - ❌ Связи между модулями не показаны
    - ❌ Зависимости не учтены
    - ⚠️ Менее структурированный ответ

### Ожидаемый результат

**Ответ с Neo4j включает:**

```
Аутентификация пользователя реализована в следующих компонентах:

1. Основной модуль: src/auth/authentication.ts
   - Функция authenticateUser()
   - Валидация токенов

2. Связанные модули:
   - src/auth/session.ts - управление сессиями
   - src/middleware/auth-middleware.ts - защита роутов
   - src/models/user.ts - модель пользователя

3. Зависимости:
   - Использует: jwt-library для токенов
   - Взаимодействует с: database service
   - Вызывается из: API endpoints

Граф зависимостей показывает, что изменения в authentication.ts
могут повлиять на 12 других файлов в проекте.
```

## Сценарий 2: Impact Analysis при рефакторинге

### Цель

Показать, как Neo4j помогает оценить влияние изменений кода.

### Шаги

1. **Выберите функцию для рефакторинга**, например:

    ```typescript
    // src/utils/validation.ts
    export function validateEmail(email: string): boolean {
    	return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)
    }
    ```

2. **Задайте вопрос в AlfaCode assistant:**

    ```
    Если я изменю функцию validateEmail, какие файлы будут затронуты?
    ```

3. **Проверьте в Neo4j Browser** (опционально):
    ```cypher
    MATCH (source:File {path: "**/validation.ts"})
    -[:EXPORTS]->(func:Function {name: "validateEmail"})
    -[:IMPORTED_BY*1..3]->(dependent:File)
    RETURN dependent.path, count(*) as usage_count
    ORDER BY usage_count DESC
    ```

### Ожидаемый результат

**С Neo4j:**

```
Изменение validateEmail повлияет на следующие файлы:

Прямые зависимости (8 файлов):
1. src/auth/registration.ts - 3 использования
2. src/components/UserForm.tsx - 2 использования
3. src/api/user-routes.ts - 1 использование
...

Косвенные зависимости (15 файлов):
- Файлы, которые импортируют вышеуказанные модули
- Рекомендуется проверить тесты

Рекомендации:
- Обновить 5 тестовых файлов
- Проверить API контракты
- Возможна миграция данных
```

**Без Neo4j:**

```
Функция validateEmail используется в нескольких файлах.
Рекомендую проверить все импорты.
```

## Сценарий 3: Навигация по зависимостям

### Цель

Демонстрация навигации по сложной структуре зависимостей.

### Шаги

1. **Выберите компонент с зависимостями:**

    ```
    Покажи все зависимости компонента UserDashboard
    ```

2. **Анализ с Neo4j:**

    - Граф показывает прямые и косвенные зависимости
    - Выявляет циклические зависимости (если есть)
    - Показывает слои архитектуры

3. **Визуализация в Neo4j Browser:**
    ```cypher
    MATCH path = (source:Component {name: "UserDashboard"})
    -[:DEPENDS_ON*1..3]->(dependency)
    RETURN path
    LIMIT 50
    ```

### Ожидаемый результат

**Визуализация покажет:**

```
UserDashboard
├── React (библиотека)
├── UserService (слой сервисов)
│   ├── ApiClient (HTTP клиент)
│   └── AuthService (аутентификация)
├── UserModel (модель данных)
└── UI Components
    ├── Avatar
    ├── StatusBadge
    └── ActionMenu
```

**Предупреждения:**

- ⚠️ Обнаружена циклическая зависимость: UserService ↔ NotificationService
- 💡 Рекомендация: рефакторинг для разрыва цикла

## Сценарий 4: Поиск дублирования кода

### Цель

Найти похожие функции и потенциальные дубликаты.

### Шаги

1. **Запрос в AlfaCode assistant:**

    ```
    Найди все функции, которые делают валидацию email
    ```

2. **Hybrid Search находит:**

    - Семантически похожие функции (Qdrant)
    - Функции с похожими именами (Neo4j)
    - Импорты и использование (Neo4j)

3. **Анализ в Neo4j:**
    ```cypher
    MATCH (f:Function)
    WHERE f.name CONTAINS "email"
       OR f.name CONTAINS "validate"
    RETURN f.name, f.file, f.signature
    ```

### Ожидаемый результат

**Найденные дубликаты:**

```
Обнаружено 4 похожие функции валидации email:

1. validateEmail() в src/utils/validation.ts
   - Используется в 8 файлах
   - Регулярное выражение: простая проверка

2. isValidEmail() в src/auth/validators.ts
   - Используется в 3 файлах
   - Более строгая валидация

3. checkEmailFormat() в src/components/forms/helpers.ts
   - Используется в 2 файлах
   - Идентична validateEmail()

4. validateEmailAddress() в src/legacy/utils.ts
   - Не используется (можно удалить)

Рекомендации:
✅ Объединить функции 1 и 3 (идентичны)
✅ Удалить функцию 4 (не используется)
⚠️  Проверить функцию 2 (другая логика, возможно нужна)
```

## Troubleshooting

### Проблема: Neo4j не отвечает

**Решение:**

```bash
# Проверьте статус сервиса
Get-Service Neo4j

# Перезапустите если нужно
Restart-Service Neo4j

# Проверьте логи
cat C:\Neo4j\logs\neo4j.log
```

### Проблема: Медленные запросы

**Решение:**

```cypher
-- Проверьте индексы
CALL db.indexes()

-- Создайте недостающие индексы
CREATE INDEX file_path_index FOR (f:File) ON (f.path)
CREATE INDEX function_name_index FOR (fn:Function) ON (fn.name)
```

### Проблема: Не все файлы в графе

**Решение:**

1. Проверьте, что индексация завершена
2. Проверьте `.kilocodeignore` - возможно файлы исключены
3. Переиндексируйте проект
