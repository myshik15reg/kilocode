# Коммит текущих изменений

## Требования
- [ ] Зафиксировать выбранный пользователем скоуп изменений в git.
- [ ] Использовать Conventional Commits и при необходимости разбить изменения на атомарные коммиты.
- [ ] Перед коммитом выполнить требуемые проверки (lint/tests/coverage) или оформить отклонение по waiver.

## Принципы проектирования и стиля
- [ ] Не усложнять решение: без оверинжиниринга при сохранении требуемой функциональности.
- [ ] Решать проблемы самым простым способом.
- [ ] Использовать и переиспользовать существующие сущности; не создавать новые без необходимости.
- [ ] Доверять фреймворкам и не делать ненужных слоев оберток.
- [ ] Не вводить слои абстракции без необходимости.

## Критерии готовности (DoD)
- [ ] Скоуп подтверждён пользователем.
- [ ] Коммит(ы) созданы с корректными сообщениями Conventional Commits.
- [ ] Проверки качества выполнены или оформлен waiver.
- [ ] `git status` чистый (или есть согласованные исключения).
- [ ] `plan.md` обновлён по шагам; `execution.md` заполнен при отклонениях.
