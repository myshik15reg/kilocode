# Протокол: исправление devcontainer postCreateCommand (CRLF + переход в каталог)

## Контекст
- Ошибка CRLF в .devcontainer/setup.sh приводит к ошибкам вида /bin/bash^M.
- Скрипт жёстко переходит в /workspace, что ломает запуск вне этого пути.
- postCreateCommand в devcontainer.json вызывает setup.sh с аргументами вместо последовательных команд.

## Цель
Обеспечить корректную инициализацию devcontainer: скрипт работает из корня репозитория, зависимости устанавливаются из requirements.txt, каталоги настроек создаются.

## Требования
1. Привести окончания строк .devcontainer/setup.sh к LF.
2. Обновить переход в корневой каталог через директорию скрипта.
3. Исправить postCreateCommand: запуск setup.sh, затем установка зависимостей из requirements.txt, затем создание каталогов настроек.
4. Опционально: зафиксировать механизм предотвращения CRLF в shell-скриптах.

## Ограничения и допущения
- requirements.txt не найден в текущем сканировании репозитория; требуется подтвердить путь.
- Изменения ограничены devcontainer-конфигурацией и setup.sh.

## Риски
- Неверный путь к requirements.txt приведёт к сбою postCreateCommand.
- Жёсткие пути в postCreateCommand могут быть неуниверсальны для других окружений.

## Критерии приемки
- setup.sh выполняется без CRLF-ошибок.
- postCreateCommand последовательно выполняет: setup.sh → pip install -r requirements.txt → mkdir -p <dirs>.
- Каталоги настроек создаются и доступны после старта контейнера.
